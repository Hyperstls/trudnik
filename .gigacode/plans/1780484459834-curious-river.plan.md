# План реализации полной логики жизненного цикла задания

## Обзор

Реализовать полную логику жизненного цикла задания со следующими состояниями:
- `open` - задание опубликовано
- `in_progress` - задание в работе (начало смены)
- `active` - смена активна (чек-ин работника)
- `payment_pending` - ожидание подтверждения оплаты
- `paid` - оплата подтверждена
- `cancelled` - задание отозвано
- `disputed` - спор по оплате

## Текущее состояние

### Существующие таблицы:
- `jobs` - задания (с полем `status`)
- `applications` - отклики (с полем `status`)
- `shifts` - смены (с полем `status`)
- `profiles` - профили пользователей

### Существующие статусы:
- `jobs.status`: open, in_progress, completed, cancelled
- `applications.status`: pending, accepted, rejected
- `shifts.status`: pending, active, payment_pending

## План реализации

### Этап 1: Обновление модели данных

#### 1.1 Добавить поля в таблицу `jobs` (ВЫПОЛНЕНО):
- `max_workers INTEGER` - максимальное количество работников
- `current_workers INTEGER` - текущее количество принятых работников (DEFAULT 0)

**Миграция создана:** `migrations/add_max_workers.sql`

#### 1.2 Добавить таблицу `ratings` для оценок (ВЫПОЛНЕНО):
```sql
CREATE TABLE IF NOT EXISTS ratings (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    rated_user_id UUID REFERENCES auth.users(id) NOT NULL,
    rater_user_id UUID REFERENCES auth.users(id) NOT NULL,
    rating_type VARCHAR(20) NOT NULL CHECK (rating_type IN ('worker', 'employer')),
    target_type VARCHAR(20) NOT NULL CHECK (target_type IN ('worker', 'employer')),
    rating INTEGER NOT NULL CHECK (rating >= 1 AND rating <= 5),
    comment TEXT,
    shift_id UUID REFERENCES shifts(id),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(rated_user_id, rater_user_id, shift_id)
);
```

#### 1.3 Добавить таблицу `notifications` для уведомлений (ВЫПОЛНЕНО):
```sql
CREATE TABLE IF NOT EXISTS notifications (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES auth.users(id) NOT NULL,
    type VARCHAR(50) NOT NULL CHECK (type IN (
        'job_created', 'job_updated', 'job_cancelled', 'job_deleted',
        'application_received', 'application_accepted', 'application_rejected',
        'shift_started', 'shift_completed', 'shift_confirmed', 'shift_disputed',
        'payment_received', 'payment_sent', 'rating_received', 'dispute_started',
        'dispute_resolved'
    )),
    title TEXT NOT NULL,
    message TEXT,
    job_id UUID REFERENCES jobs(id),
    shift_id UUID REFERENCES shifts(id),
    application_id UUID REFERENCES applications(id),
    is_read BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### Этап 2: Маршруты Flask

#### 2.1 Редактирование задания:
```
POST /job/edit/<job_id>
- Проверка: статус = 'open' ИЛИ (статус = 'cancelled' и нет принятых откликов)
- Обновление полей задания
```

#### 2.2 Отзыв задания:
```
POST /job/cancel/<job_id>
- Проверка: до начала смены > 12 часов
- Автоматическое отклонение непринятых откликов
- Отправка уведомлений работодателю и работникам
```

#### 2.3 Восстановление задания:
```
POST /job/restore/<job_id>
- Изменение статуса 'cancelled' → 'open'
```

#### 2.4 Принятие отклика:
```
POST /application/<app_id>/accept
- Проверка: статус задания = 'open' ИЛИ 'in_progress'
- Проверка: current_workers < max_workers
- Обновление статуса отклика → 'accepted'
- Увеличение current_workers
- Создание смены
```

#### 2.5 Отзыв принятого работника:
```
POST /application/<app_id>/cancel
- Проверка: до начала смены > 12 часов
- Уменьшение current_workers
- Возврат статуса задания в 'open' если current_workers = 0
```

#### 2.6 Чек-ин работника:
```
POST /shift/<shift_id>/checkin
- Изменение статуса 'pending' → 'active'
- Запись checkin_time
```

#### 2.7 Завершение смены:
```
POST /shift/<shift_id>/complete
- Изменение статуса 'active' → 'payment_pending'
- Запись complete_time
```

#### 2.8 Подтверждение оплаты работодателем:
```
POST /shift/<shift_id>/confirm-payment-employer
- Установка employer_payment_confirmed = TRUE
- Если обе стороны подтвердили → 'paid'
```

#### 2.9 Подтверждение оплаты работником:
```
POST /shift/<shift_id>/confirm-payment-worker
- Установка worker_payment_confirmed = TRUE
- Если обе стороны подтвердили → 'paid'
```

#### 2.10 Оценка работника:
```
POST /rate-worker/<worker_id>/<job_id>
- Проверка: статус = 'paid'
- Создание записи в ratings
- Обновление среднего рейтинга в profiles
```

#### 2.11 Запрос спора:
```
POST /shift/<shift_id>/dispute
- Изменение статуса на 'disputed'
- Уведомление администратора
```
