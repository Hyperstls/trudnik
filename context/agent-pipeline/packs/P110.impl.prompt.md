## 1. Цель (goal)

Профиль, созданный через ORM (create_user), по умолчанию не подтверждён и не может войти до email-верификации; суперпользователь и тестовые verified-фикстуры остаются подтверждёнными.

## 2. Зачем (why)

Модель Profile.email_verified default=True — fail-open: любой путь создания профиля в обход RPC даёт подтверждённого пользователя (AUTH-P1-10). DB-default остаётся true до P113; ORM-путь закрываем сейчас.

## 4. Интерфейсы (не выдумывать и не «улучшать»)

Profile.email_verified: default=False. ProfileManager.create_user не должен принудительно ставить True (модельный default работает); create_superuser по-прежнему ставит email_verified=True. В tests/test_auth.py make_profile по умолчанию ставит email_verified=True (это фикстура подтверждённого пользователя), explicit email_verified=False сохраняется. Тест test_create_user_is_unverified_by_default: create_user -> email_verified False; client.login -> False. Существующий test_login_unverified_email_rejected и test_admin_flags_from_role остаются зелёными.

## 5. Критерии приёмки

1. Profile.email_verified default=False.
2. create_user создаёт неподтверждённого пользователя; login запрещён до верификации.
3. create_superuser создаёт подтверждённого администратора.
4. make_profile по умолчанию verified; explicit email_verified=False работает.
5. core.tests.test_auth и core.tests.test_auth_flows проходят.

## 9. Типовые ловушки (реальные ошибки, стоившие раундов):
1. Контракт ссылается на канон проекта, а не на самодельные регэкспы.
2. Кэш: ключ включает ВСЁ, от чего зависит результат; ветка кэш-хита проходит ту же валидацию.
3. Счётчики не врут молча: метрику, которая должна делиться по каналам/типам, дели сразу.
4. Фолбэк «нет данных — подставь само значение» — дыра в инварианте. Формулируй, что НЕЛЬЗЯ.
5. Контракт может быть неправ, а код — прав. Сначала проверь выполнимость требования.
6. Ревьюер — отдельный вызов с лимитом контекста: заголовок и критерии → grep → range-чтения.
7. Другие процессы портят scope. Отсюда baseline и spill-исключения; `--skip-scope` — только со следом.
8. Windows/оболочки: `>` в PowerShell = UTF-16LE; `&&` может не поддерживаться; `$d:` ломает парсер.
9. JSON-контракты пиши инструментом записи целиком, а не точечными правками со вставками `\n`.
10. «Проверено» должно быть доказуемым: у факта — ссылка на источник, у отсечённого — причина.
11. Лимит раундов: 2 узких фикса на задачу. Дальше `blocked` и вопрос человеку.
