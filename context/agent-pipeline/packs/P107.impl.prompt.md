## 1. Цель (goal)

Документ верификации принимает PDF/JPEG/PNG/WebP по magic bytes; аватары и фото заданий по-прежнему только изображения.

## 2. Зачем (why)

Flask принимал PDF/JPG/PNG, Django отвергает PDF (AUTH-P1-07).

## 4. Интерфейсы (не выдумывать и не «улучшать»)

storage.detect_extension(data, allow_pdf=False): JPEG/PNG/WebP всегда; PDF (b'%PDF-') только при allow_pdf=True. save_upload(uploaded_file, subdir, allow_pdf=False) передаёт флаг; upload_verification_doc вызывает save_upload(..., allow_pdf=True); upload_avatar и job_photo_upload — без флага. verify_employer.html: accept='.pdf,image/jpeg,image/png,image/webp', текст 'PDF, JPEG, PNG или WebP до 5 МБ'. Тесты UploadTests: test_verification_pdf_accepted (PDF -> 302, verification_doc_url оканчивается .pdf, файл существует), test_avatar_pdf_rejected (PDF в avatar -> avatar_url не меняется).

## 5. Критерии приёмки

1. PDF принимается только для verification-docs; avatar/job photo PDF отклоняют.
2. upload_verification_doc сохраняет .pdf и ставит verification_status=pending.
3. Шаблон верификации принимает PDF и сообщает об этом.
4. core.tests.test_parity_ext.UploadTests проходит.

## 6. Вне scope (запрещено)

- Не менять лимит размера и проверку magic bytes изображений.
- Не менять ACL verification-docs (P002).

## 9. Типовые ловушки (реальные ошибки, стоившие раундов):
1. Контракт ссылается на канон проекта, а не на самодельные регэкспы.
2. Кэш: ключ включает ВСЁ, от чего зависит результат; ветка кэш-хита проходит ту же валидацию.
3. Счётчики не врут молча: метрику, которая должна делиться по каналам/типам, дели сразу.
4. Фолбэк «нет данных — подставь само значение» — дыра в инварианте. Формулируй, что НЕЛЬЗЯ.
5. Контракт может быть неправ, а код — прав. Сначала проверь выполнимость требования.
6. Ревьюер — отдельный вызов с лимитом контекста: заголовок и критерии → grep → range-чтения.
7. Другие процессы портят scope. Отсюда baseline и spill-исключения; `--skip-scope` — только со следом.
8. Windows/оболочки: `>` в PowerShell = UTF-16LE; `&&` может не поддерживаться; `$d:` ломает парсер.
9. JSON-контракты пиши инструментом записи целиком, а не точечными правками со вставками `\n`.
10. «Проверено» должно быть доказуемым: у факта — ссылка на источник, у отсечённого — причина.
11. Лимит раундов: 2 узких фикса на задачу. Дальше `blocked` и вопрос человеку.
