Документ верификации отдаётся только владельцу профиля или администратору; остальным — 404; ответ private/no-store и attachment.

## 4. Интерфейсы (не выдумывать и не «улучшать»)

serve_upload(request, path): для path.startswith('verification-docs/') требовать request.user.is_authenticated; владелец = Profile.objects.filter(verification_doc_url='/uploads/'+path).first(); разрешить, если profile.pk == request.user.pk или request.user.role == 'admin'; иначе Http404. Для verification-docs: FileResponse(..., as_attachment=True), Cache-Control: private, no-store, X-Content-Type-Options: nosniff. Для avatars/jobs сохранить public, max-age=86400. Тесты в core.tests.test_parity_ext.UploadTests: guest/other/owner/admin, headers, traversal.

## 5. Критерии приёмки

1. Guest GET verification-doc → 404 (не 200 и не отдача содержимого).
2. Авторизованный не-владелец → 404.
3. Владелец (Profile.verification_doc_url совпадает) → 200.
4. Администратор (role='admin') → 200.
5. Ответ verification-doc: Cache-Control содержит private и no-store; Content-Disposition содержит attachment.
6. Path traversal → 404 (существующий тест).
7. Avatars/jobs остаются публичными с Cache-Control public.

## 9. Типовые ловушки (реальные ошибки, стоившие раундов):
1. Контракт ссылается на канон проекта, а не на самодельные регэкспы.
2. Кэш: ключ включает ВСЁ, от чего зависит результат; ветка кэш-хита проходит ту же валидацию.
3. Счётчики не врут молча: метрику, которая должна делиться по каналам/типам, дели сразу.
4. Фолбэк «нет данных — подставь само значение» — дыра в инварианте. Формулируй, что НЕЛЬЗЯ.
5. Контракт может быть неправ, а код — прав. Сначала проверь выполнимость требования.
6. Ревьюер — отдельный вызов с лимитом контекста: заголовок и критерии → grep → range-чтения.
7. Другие процессы портят scope. Отсюда baseline и spill-исключения; `--skip-scope` — только со следом.
8. Windows/оболочки: `>` в PowerShell = UTF-16LE; `&&` может не поддерживаться; `$d:` ломает парсер.
9. JSON-контракты пиши инструментом записи целиком, а не точечными правками со вставками `\n`.
10. «Проверено» должно быть доказуемым: у факта — ссылка на источник, у отсечённого — причина.
11. Лимит раундов: 2 узких фикса на задачу. Дальше `blocked` и вопрос человеку.
