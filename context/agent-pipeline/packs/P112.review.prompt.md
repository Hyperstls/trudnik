## 1. Цель (goal)

Пользователь A не может читать/менять/удалять данные B через profile/edit/export/delete/report; session identity не подменяется.

## 2. Критерии приёмки

1. A не может изменить профиль B через POST /profile.
2. Экспорт A не содержит данных B.
3. A может удалить только себя; B остаётся.
4. Жалоба фиксирует reporter=A, reported=B; self-report отклоняется.
5. Verification-doc other-user 404 (P002) остаётся зелёным.
6. core.tests.test_profile_flows и core.tests.test_parity_ext проходят.

## 3. Вне scope

- Не менять production-код; это контрактная проверка компенсации RLS.
- Не менять другие области (jobs/applications/chat).
