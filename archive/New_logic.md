## Статусы задания
| Статус | Описание |
|--------|----------|
| **`open`** | Задание опубликовано, идёт приём откликов. |

| **`active`** | `accepted` | ✅ Написать в чат |
| **`completed`** | `accepted` | ✅ Оценить работодателя |

## Автоматические переходы и ограничения

- **`open` → `in_progress`**: когда `current_workers >= max_workers` (все места заняты). При отзыве принятого отклика и снижении `current_workers` статус возвращается в `open`.
- **`in_progress` → `active`**: автоматически при наступлении времени начала задания (`date_time`), даже если не все места заняты.
- **Отзыв отклика работником**:
  - Если отклик `pending` – можно отозвать в любое время.
  - Если отклик `accepted` – можно отозвать **не позднее чем за 12 часов до начала**.
- **Завершение задания работодателем**: доступно в статусе `active` (после наступления времени начала). При завершении все непринятые отклики автоматически отклоняются, принятые остаются с отметкой о завершении. Задание переходит в `completed`.
- **Восстановление из `cancelled`**: при восстановлении задания (`open`) все старые отклики удаляются или помечаются неактивными.

## Изменения в базе данных

1. **Таблица `shifts`** больше не используется. Чат привязывается к отклику (`application_id`).
   - В таблице `messages` добавляется столбец `application_id` (UUID, ссылка на `applications.id`).
   - Чат создаётся сразу после принятия отклика (статус `accepted`).
   - При отзыве работника история чата может сохраняться или удаляться (на усмотрение разработчика).

2. **Таблица `jobs`**: исключаются статусы `active`, `payment_pending`, `paid`, `disputed`. Остаются: `open`, `in_progress`, `completed`, `cancelled`.

3. **Таблица `applications`**: сохраняет поле `status` (`pending`, `accepted`, `rejected`). Опционально можно добавить флаг `archived` для логического удаления.

4. **Удаляются маршруты**, связанные с чек-инами, завершением смены, подтверждением оплаты, спорами. Добавляется маршрут принудительного завершения задания работодателем.

5. **Оценка** возможна только после перехода задания в статус `completed`. Оценить можно каждого принятого работника или работодателя один раз.

6. **Чат** становится доступным с момента принятия отклика. Кнопка «Написать» отображается:
   - У работодателя — в карточке принятого отклика.
   - У работника — в карточке задания, если его отклик принят.

## 🧪 EDGE CASES

### ⏰ Симуляция времени (Playwright Clock + SQL)
```javascript
// Тест перехода in_progress → active по date_time
const jobId = await createJob({ 
    max_workers: 3, 
    date_time: '2026-06-14T10:00:00Z' // через 1 час
});

// Проверяем, что сейчас in_progress
await expectJobStatus(jobId, 'in_progress');

// Мотаем время вперёд
await page.clock.fastForward('01:01:00'); // +1 час 1 минута

// Обновляем страницу или делаем триггер-запрос
await page.reload();
await expectJobStatus(jobId, 'active'); // Должен стать active
```

### 🔄 Множественные отзывы (каскад переходов)
1. Задание `max_workers=3`, принято 3 → статус `in_progress`
2. Трудник 1 отзывает → `current=2`, статус → **`open`** (не остаётся `in_progress`!)
3. Новый трудник откликается и принимается → `current=3`, статус → **`in_progress`**
4. Трудник 2 отзывает → `current=2`, статус → **`open`**
5. **Проверка:** Все переходы корректны, UI обновляется

### ⚡ Принудительное завершение с разными типами откликов
1. Задание `active`, есть: 2 `accepted`, 3 `pending`, 1 `rejected`
2. Работодатель жмёт "Завершить"
3. **Проверка БД:**
   - `jobs.status = completed`
   - 2 `accepted` остаются со специальным флагом завершения
   - 3 `pending` → `rejected` (массовое обновление)
   - 1 `rejected` остаётся `rejected`
4. **Проверка UI:** 2 трудника с `accepted` могут оценить, 3 с `pending` — нет
