# Инструкция по архивации файлов

## Правила

**Все ненужные файлы должны перемещаться в папку `archive/`**

### Что перемещать в archive:
1. ✅ Старые инструкции (DEPLOY_INSTRUCTION.txt, INSTRUCTION_*.txt)
2. ✅ Устаревшие скрипты (auto_fix_agent.py, browser_agent.py, deploy_pa.py, reload_pa.py)
3. ✅ Старые отчёты (CHECK_STATUS.txt, FINAL_SUMMARY_*.txt, OPTIMIZATION_PLAN.txt)
4. ✅ Дубликаты файлов
5. ✅ Временные файлы

### Что оставлять в корне:
- `app.py`, `config.py`, `requirements.txt` — основные файлы
- `templates/`, `static/`, `migrations/` — папки с кодом
- `README.md`, `PROJECT_CONTEXT.md` — документация
- `deploy_pythonanywhere.bat`, `deploy_pythonanywhere.sh` — актуальные скрипты
- `.env` — конфигурация (в .gitignore)
- `.gigacode/` — конфигурация AI-агента

### Что оставлять в корне (новые файлы):
- Все новые инструкции по деплою (DEPLOY_INSTRUCTION_PA.txt)
- Все новые скрипты деплоя (deploy_pythonanywhere.bat, deploy_pythonanywhere.sh)
- Миграции (migrations/*.sql)
- Все новые файлы, относящиеся к активной разработке

## Структура archive/

```
archive/
├── auto_fix_agent.py
├── browser_agent.py
├── check_*.py
├── deploy_*.py
├── reload_pa.py
├── test_runner.py
├── *.txt (старые инструкции и отчёты)
├── .git_commit_msg
```

## Будущие действия

1. **При создании новых файлов** — сначала подумайте, нужны ли они в корне
2. **При замене файлов** — старые перемещайте в `archive/`
3. **При устаревании инструкций** — перемещайте в `archive/`
4. **При переименовании** — оставляйте старые версии в `archive/`

## Использование архива

При необходимости обратиться к старым файлам:
- Используйте путь `archive/filename`
- Например: `archive/CHECK_STATUS.txt`
- Или посмотрите историю изменений через git
