## План реализации

### Файл 1: `test_selenium_v2.py` — дополнить

Добавить тесты:
- `t_register_worker()` — регистрация нового трудника через /register
- `t_boundary_email()` — невалидный email в форме входа
- `t_boundary_empty_fields()` — отправка пустой формы создания задания
- `t_boundary_long_input()` — сверхдлинный ввод в поле названия
- `t_rls_worker_cant_see_myjobs()` — трудник не должен видеть /my-jobs
- `t_rls_employer_cant_see_myapps()` — работодатель без заданий не видит чужие отклики
- `t_responsive_mobile()` — проверка на мобильном viewport (390×844)
- `t_admin_block_unblock()` — админ блокирует/разблокирует пользователя

### Файл 2: `test_api.py` — создать

Тесты через `requests` к `http://127.0.0.1:5000`:
- `test_api_health()` — GET / → 200
- `test_api_skills()` — GET /api/skills → 200 + JSON
- `test_api_religions()` — GET /api/religions → 200 + JSON
- `test_api_jobs_public()` — GET /api/jobs (публичный список)
- `test_api_login_success()` — POST /login → 302 + session
- `test_api_login_wrong_password()` — POST /login → 200 (не уходит с login)
- `test_api_register_duplicate()` — POST /register с существующим email
- `test_api_myjobs_unauthorized()` — GET /my-jobs без сессии → 302 на /login
- `test_api_myjobs_as_worker()` — GET /my-jobs с сессией трудника → 302 (доступ запрещён)
- `test_api_admin_unauthorized()` — GET /admin без сессии → 302 на /login
- `test_api_csrf_protection()` — POST без CSRF-токена → 400

### Файл 3: `test_rls.py` — создать (RLS проверки через Supabase API)

- `test_rls_anon_cant_list_jobs()` — анонимный запрос к Supabase jobs
- `test_rls_worker_sees_only_open_jobs()` — трудник видит только open
- `test_rls_employer_sees_only_own_jobs()` — работодатель видит только свои
- `test_rls_worker_cant_modify_job()` — трудник не может PATCH чужое задание
- `test_rls_no_using_true_policy()` — проверка отсутствия USING(true) в политиках
