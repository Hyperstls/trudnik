# План: Приведение кода в соответствие с матрицей статусов и операций

## Статус: Анализ завершён, готов к реализации

## Консолидированная модель статусов

### Задания (jobs.status)
```
open → in_progress → active → payment_pending → paid → completed
  ↓                                                     ↑
cancelled ←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←← disputed
```

### Смены (shifts.status)
```
pending → active → payment_pending → paid → completed
                              ↓
                          disputed
```

## Обнаруженные расхождения и план исправлений

### Шаг 1: Исправить шаблон `templates/my_jobs.html` — статистика и табы

**Файл:** [`templates/my_jobs.html`](templates/my_jobs.html:20)

**Проблема:** Статистика и табы фильтрации не включают статусы `active`, `payment_pending`, `paid`.

**Исправление:**
- В блоке статистики (строки 20-36) добавить подсчёт `active_count`, `payment_pending_count`, `paid_count` и их отображение
- В табах фильтрации (строки 42-63) добавить табы: «Активные» (`active`), «Ожидает оплаты» (`payment_pending`), «Оплачено» (`paid`)
- Добавить CSS-классы для статус-бейджей `active`, `payment_pending`, `paid` (строки 122-130)

### Шаг 2: Исправить шаблон `templates/my_jobs.html` — кнопки действий

**Файл:** [`templates/my_jobs.html`](templates/my_jobs.html:159)

**Проблема:** Нет кнопок «Подтвердить оплату» для `payment_pending` и «Оценить работника» для `paid`.

**Исправление:**
- Для `job.status == 'payment_pending'`: добавить кнопку «Подтвердить оплату» (переход на shifts или прямой вызов)
- Для `job.status == 'paid'`: добавить кнопку «Оценить работника» (ссылка на форму оценки)
- Проверить видимость кнопок согласно матрице:
  - `open`: Редактировать, Отозвать, Дублировать, Удалить
  - `in_progress`: Отозвать, Дублировать, Удалить
  - `active`: Дублировать, Удалить (отозвать нельзя — проверка в бэкенде)
  - `payment_pending`: Дублировать, Удалить, Подтвердить оплату
  - `paid`: Дублировать, Удалить, Оценить работника
  - `completed`: Дублировать, Удалить
  - `cancelled`: Вернуть, Дублировать, Удалить

### Шаг 3: Блокировка отзыва задания с активными сменами

**Файл:** [`app/blueprints/jobs.py`](app/blueprints/jobs.py:524) — функция `cancel_job`

**Проблема:** Нет проверки на наличие активных смен перед отзывом задания.

**Исправление:**
- Перед `PATCH jobs SET status = 'cancelled'` проверить через `supabase_request` наличие смен со статусом `active` для этого задания
- Если есть активные смены — вернуть ошибку (flash + redirect или JSON error для AJAX)

### Шаг 4: Блокировка удаления задания с принятыми откликами

**Файл:** [`app/blueprints/jobs.py`](app/blueprints/jobs.py:550) — функция `delete_job`

**Проблема:** Нет проверки на наличие принятых откликов перед удалением.

**Исправление:**
- Перед `DELETE jobs` проверить через `supabase_request` наличие откликов со статусом `accepted` для этого задания
- Если есть — требовать подтверждения или блокировать удаление
