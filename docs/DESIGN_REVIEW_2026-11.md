# UX/UI-ревью «Трудник» — ноябрь 2026

**Роль:** независимая оценка как product/UX-дизайнер.
**Объект:** прод `трудник.рф`, Django-версия; мобильный 390–444 px и десктоп.
**Метод:** эвристики Нильсена, инвентаризация кликабельных элементов, проверка
сценариев «найти → откликнуться → принять → чат → завершить → оценить», анализ
мобильных скриншотов и шаблонов.

## Оценка

| Критерий | Оценка | Комментарий |
|---|---:|---|
| Визуальная целостность | 8/10 | тёплая брендовая палитра, единые карточки, скругления, Inter |
| Информационная архитектура | 7/10 | 5 пунктов навигации, понятные разделы; не хватает активного состояния и группировки фильтров |
| Usability ключевых сценариев | 7.5/10 | размещение/отклик/принятие/чат работают; фильтры и мобильные действия перегружены |
| Мобильный опыт | 7/10 | bottom-nav и адаптив есть; фильтры и панели действий всё ещё плотные |
| Доступность | 7/10 | skip-link, label, dialog, aria есть; контраст метаданных и focus-ring местами слабые |
| Доверие/безопасность в UI | 8/10 | верификация, «Безопасная сделка», контакты после отклика, приватность гео |
| Скорость восприятия | 7.5/10 | server-rendered, N+1 в чатах убран; нет skeleton для асинхронных блоков |
| **Итог** | **7.6/10** | крепкий продуктовый UI; следующий рост — системность и снижение когнитивной нагрузки |

## Что уже работает хорошо

- **Единый бренд:** тёплый янтарный primary, нейтральная база, одинаковые радиусы/тени.
- **Понятная модель:** «Задания», «Отклики», «Чаты», «Избранное», «Трудники»; на мобильном —
  bottom-nav.
- **Ключевые действия рядом с контекстом:** «Откликнуться» в карточке, «Принять/Отклонить»
  в откликах, «Чат» у принятого, «Оценить» после завершения.
- **Пустые состояния и ошибки** есть на большинстве страниц, тексты на русском и по делу.
- **Доверие:** бейдж «Проверен», отзывы, trust-блок, контакты только после отклика.
- **Гео-сценарий:** карта только для офлайн-заданий, маршрут, геокодинг, приватность
  координат (сессия, округление, без URL).
- **Доступность:** `<dialog>` для жалобы, aria-label, skip-link, reduced-motion.

## Проблемы и решения

### P1 — заметно влияет на конверсию/ошибки

1. **Плотность фильтров на мобильном.**
   Радиус, гео, оплата, навыки, «Все задания», «Применить» стоят в одном flex-ряду и
   конкурируют за место; выпадающая панель навыков перекрывает «Применить».
   **Решение:** на `<640px` — кнопка «Фильтры» с бейджем активных, открывающая bottom-sheet;
   внутри — секции «Гео», «Оплата», «Навыки», sticky-футер «Сбросить / Применить».
   На десктопе — текущий inline-фильтр, но с группами и подписями.

2. **Иерархия действий в карточках.**
   «Отклики», «Изменить», «Отменить», «Завершить», «Удалить» визуально равны; на мобильном
   занимают несколько строк.
   **Решение:** одно primary-действие по статусу + меню «⋯» для остальных; destructive —
   только в меню с подтверждением. Это уменьшит случайные удаления/отмены.

3. **Контраст метаданных.**
   `text-neutral-400` на белом для дат/подсказок ниже 4.5:1.
   **Решение:** для смыслового текста — `neutral-500/600`; `neutral-400` оставить только
   декоративным иконкам. Добавить проверку контраста в pre-deploy (пары цветов).

4. **Нет активного состояния навигации.**
   Пользователь не видит, в каком разделе находится.
   **Решение:** `aria-current="page"` + цвет/подчёркивание активного пункта в desktop/mobile.

### P2 — удобство и современность

5. **Формы длинные, без прогресса.** Регистрация и создание задания — длинный скролл.
   **Решение:** секции/степпер (1. Что за работа → 2. Где/когда → 3. Оплата → 4. Контакты),
   автосохранение черновика в localStorage, inline-валидация на blur, «Сохранить и выйти».

6. **Карта: нет подсказок адреса и явного подтверждения точки.**
   **Решение:** Yandex Suggest для address/city, чип «Адрес найден: …», кнопка
   «Подтвердить точку», перетаскиваемая метка с крупным hit-area; при геолокации —
   «Вы здесь?» и возможность поправить. Показывать радиус поиска кругом на карте ленты.

7. **Push-разрешение запрашивается не вовремя.**
   **Решение:** не спрашивать при загрузке; объяснить пользу в настройках и запрашивать после
   первого полезного действия (отклик/создание задания).

8. **Уведомления без группировки.**
   **Решение:** группировать по типу/заданию, показывать непрочитанные секцией, добавить
   «Отметить всё» и фильтр «Только важные»; deep-link уже есть.

9. **Разные пустые состояния и CTA.**
   **Решение:** единый компонент EmptyState (иконка, заголовок, пояснение, 1 primary + 1
   secondary CTA), одинаковые отступы.

10. **Чат: нет состояний отправки/ошибки.**
    **Решение:** optimistic bubble с «часиками», retry при ошибке, «не отправлено»,
    автоскролл только если пользователь внизу (не выдёргивать из чтения истории).

### P3 — системность и полировка

11. **Нет дизайн-токенов и компонентных макросов.** Классы и `text-[11px]` задаются точечно.
    **Решение:** tokens (color/status/spacing/radius/shadow), компоненты Button/Badge/Card/
    Field/EmptyState/Modal/Sheet в Django-макросах; запрет arbitrary values без причины.
12. **Иконки разных стилей.** Часть — inline SVG, часть — emoji/текст.
    **Решение:** один набор (например, Lucide) и размерная сетка 16/20/24.
13. **Микроанимации не systematized.** Есть fade-in, но нет единых duration/easing.
    **Решение:** 150–250 ms, ease-out; учитывать `prefers-reduced-motion`.
14. **Карта на десктопе занимает первый экран ленты.** Для пользователей без гео-запроса
   это отвлекает.
    **Решение:** сворачиваемый блок карты или карта только при активном гео/городе.

## Предлагаемая дизайн-система

- **Цвет:** primary 50–700, neutral 50–900, success/warning/danger + статусные пары
  (open/accepted/rejected/cancelled) с контрастом ≥4.5:1.
- **Типографика:** 12/14/16/20/24/30; line-height 1.4–1.6; не больше 3 размеров на экран.
- **Сетка/отступы:** 4/8/12/16/24/32; карточки radius 16, controls radius 12.
- **Компоненты:** Button (primary/secondary/ghost/danger, loading/disabled), Badge,
  Card, Field (label/hint/error), EmptyState, Modal/Dialog, BottomSheet, Tabs, Toast.
- **Состояния:** default/hover/focus-visible/active/disabled/loading/error/empty.
- **Доступность:** focus-visible ring 2–3 px, aria-current, aria-live для тостов,
  контраст текста, клавиатурные сценарии, 44×44 touch-target.

## Roadmap

**Спринт 1 (быстрые победы, 3–5 дней)**
- активная навигация + focus-visible;
- контраст метаданных;
- меню «⋯» в карточках и подтверждение destructive;
- единый EmptyState.

**Спринт 2 (мобильный UX, 1–2 недели)**
- bottom-sheet фильтров с бейджем и sticky-действиями;
- Suggest/подтверждение адреса, радиус на карте;
- skeleton для чатов/уведомлений; retry-состояния.

**Спринт 3 (системность, 2–3 недели)**
- токены + компонентные макросы;
- степпер регистрации/задания и черновик;
- группировка уведомлений, push после действия;
- UX-метрики: воронка отклика, доля успешных созданий, время до первого отклика,
  ошибки форм, Core Web Vitals.

## Метрики успеха

- Конверсия «просмотр задания → отклик» и «создание задания → публикация».
- Доля форм с ошибкой валидации и время заполнения.
- Доля мобильных сессий с открытием фильтров и применением.
- Crash/error rate, p95 TTFB/LCP, число обращений «не пришло письмо/не работает кнопка».
- A11y: 0 критичных нарушений по axe-core на топ-10 страницах.

## Уже внедрено из ревью

- J056: модалка жалобы вместо inline input.
- J059: глобальный `focus-visible` и `aria-labelledby` у диалогов.
- J053: гео-координаты не попадают в URL, округление и TTL сессии.

## Итог

Продукт выглядит цельно и вызывает доверие; основные резервы — не «перекрасить», а
**снизить плотность мобильных фильтров, systematize действия в карточках и ввести
дизайн-токены/состояния**. После этого UI станет заметно спокойнее и быстрее для
повторяющихся сценариев.
