1. **Открытый редирект в профиле** — `worker_invitations_revoke` и
   `invitation_revoke` принимали `next`, начинающийся с `/`, без проверки
   scheme-relative форм. Теперь используется
   `url_has_allowed_host_and_scheme` с проверкой HTTPS.
   Задача конвейера **R001**, verify/review — PASS, добавлены 2 регрессионных теста.
2. **Ссылки в live-уведомлениях** — `notifications-init.js` разрешал
   `http(s)` и `//`-ссылки из payload. Теперь ссылка нормализуется через
   `new URL` и допускается только same-origin; иначе — `/notifications`.
3. **Мобильная шапка** — профиль обрезался на узких экранах; на ≤420 px
   скрывается текст бренда, уменьшены отступы, действия закреплены `shrink-0`.
4. **Uptime** — транзиентные TLS/5xx от Amvera ingress давали ложные падения;
   добавлены 3 попытки с задержкой, issue автоматически закрывается после успеха.
5. **E2E** — seed-задание совпадало по названию/городу с заданием из UI и
   уходило в антифрод-модерацию; seed переименован, E2E 8/8.

## Приоритетные улучшения

### P1 — безопасность и надёжность

1. **Централизовать `safe_next`/`safe_back`.** Сейчас проверки `next`/`Referer`
   дублируются в `views.py`, `views_flow.py`, `views_profile.py`,
   `views_public_ext.py`. Нужен один helper в `core/http.py`:
   `same_origin_redirect(value, request, fallback)`, с `require_https` всегда.
2. **`legal_page` использует `|safe`.** HTML из `SitePage` может содержать
   произвольный HTML/JS при компрометации staff-аккаунта. Нужен sanitizer
   (bleach/nh3) или редактор только с разрешёнными тегами.
3. **Лимит тела MAX-webhook.** `_json_body` читает `request.body` без ограничения
   размера; добавить `Content-Length` cap (например, 64 КБ) для webhook.
4. **Проверить `Referer`-редиректы на HTTPS.** В `views_public_ext` и
   `views_flow._safe_back` не передан `require_https=request.is_secure()`.
5. **Ограничение 120 req/min на IP** может блокировать пользователей за общим
   NAT/офисом. Рассмотреть более высокий лимит для аутентифицированных,
   отдельный лимит на API и мягкий `Retry-After`.

### P1 — продукт и UX

6. **2FA и управление сессиями.** MAX-верификация — это подтверждение профиля,
   не второй фактор. Нужны TOTP/одноразовые коды и список активных сессий.
7. **Среднее время ответа** в репутации и **workflow апелляции** по скрытому
   отзыву (сейчас — через поддержку).
8. **Гонка при публикации отзывов.** Два одновременных отзыва могут не
   опубликовать друг друга до 14-дневной задачи. Добавить транзакционную
   блокировку пары или DB-функцию публикации.
9. **Пагинация `user_ratings`.** Сейчас отдаются последние 50 отзывов без
   страниц; при росте профиля нужна пагинация/фильтры.

### P2 — архитектура и качество кода

10. **Разделить крупные модули.** `views.py` (≈750 строк) и `views_flow.py`
    смешивают jobs, профиль, редиректы и утилиты. Вынести:
    `core/http.py` (redirects), `core/jobs_views.py`, `core/ratings_views.py`.
11. **Тесты JS.** Для `safeNotificationLink` и офлайн-очереди нет unit-тестов;
    добавить небольшой Node-тест или вынести чистые функции в модуль.
12. **Сохранённые поиски** хранятся в `profiles.notification_prefs` JSON.
    Для >10 поисков, истории и аналитики лучше отдельная таблица
    `saved_searches` с индексами.
13. **Метрики для рейтингов**: сколько отзывов ждёт публикации, сколько
    скрыто модерацией, средняя задержка публикации — в админ-дашборд.
14. **Расширить UX-аудит** на авторизованные страницы (`/profile`,
    `/my-applications`, `/chats`) в axe/Lighthouse, а не только публичные.
