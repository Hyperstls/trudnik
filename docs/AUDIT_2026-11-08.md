## 2. Открытые риски и действия владельца

| Риск | Почему важно | Что сделать |
|---|---|---|
| **XFF-модель Amvera не проверена (C2)** | Если платформа не дописывает `X-Forwarded-For`, последний hop контролирует клиент → обход лимитов, `AdminIpAllowlist` | один запрос с подставным XFF → сверить audit_log; при прозрачном прокси — `X-Real-IP`/счётчик hop (планируемая задача R079, контракт не создан) |
| **Prod `/privacy` = SitePage v1.2** | Шаблон v1.3 и RKN-док утверждают новые формулировки, прод отдаёт старое | обновить `site_pages` в админке до v1.3 (п. 4.2/9.1/9.2/10.7/10.8/14.5) — `LAUNCH_CHECKLIST.md` |
| **Push = трансграничная передача** | Ст. 12 152-ФЗ: декларировать или отключить канал | решение владельца, инструкция — `docs/rkn_notification_fill.md` |
| **Уведомление РКН** | Прод работает с 03.11; подать до реального набора | владелец |
| **Почтовый DNS (SPF/DKIM/DMARC)** | Письма регистрации/сброса ненадёжны | `docs/SMTP_DNS_SETUP.md` |
| **Бэкапы БД + media** | Media (`/data/uploads`) не бэкапится; restore на проде не репетирован | автоматизировать, зафиксировать RTO/RPO |
| **Нагрузочный тест** | Лимиты Amvera не проверены | 100 req, P=8 в согласованное окно |
| **DNS-rebinding product endpoints** | Домен, резолвящийся в loopback, проходит валидацию (вне scope R055/R070) | резолв+`is_global` на стороне отправки (планируемая задача R080, контракт не создан) |
| **UUID в логах client_error редактируется** | Диагностика теряет `/jobs/<uuid>` (сегмент 36 > 32) | при необходимости — редактировать только token-like сегменты |
| **Полученные сообщения не в экспорте** | Ст. 14 может толковаться шире, чем «только отправленные» | осознанное решение задокументировать или добавить |
