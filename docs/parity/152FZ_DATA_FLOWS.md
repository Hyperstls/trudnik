# 152-ФЗ: ПДн и потоки данных (актуально на 2026-11-09)

Документ фиксирует **технические** факты и остаточные риски. Правовую базу
(согласия, сроки, уведомление РКН, договоры с операторами) подтверждает владелец;
это не юридическое заключение.

## 1. Какие ПДн обрабатываются

| Категория | Где | Статус/меры |
|---|---|---|
| Email, ФИО, город, телефон | регистрация/профиль | обычные ПДн; публично не показываются |
| Контакт (`contact`), портфолио | профиль | не публично; работодатель видит контакт только после отклика (J038) |
| ИНН, самозанятость | профиль/регистрация | валидация ИНН; добровольно |
| Документ верификации (JPEG/PNG/WebP/PDF) | `/uploads/verification-docs/...` | owner/admin, `private, no-store`, attachment (J0xx/P0-02) |
| ~~Вероисповедание~~ | — | удалено из БД: колонки `profiles.religion_id`/`jobs.preferred_religion` дропнуты миграцией 164 (2026-11-08) |
| Возраст, bio, опыт, желаемая оплата, навыки | профиль | обычные ПДн |
| Аватар/фото заданий | uploads | публично (фото задания/аватар по решению владельца) |
| Сообщения, отклики, оценки, жалобы | БД | обычные ПДн; доступ по участию |
| Геопозиция пользователя (гео-фильтр) | серверная сессия | округление до 3 знаков, TTL 1 час, не в URL/логах (J053) |
| Адрес/координаты задания | БД | публичная информация о месте работы, не геолокация устройства |
| Черновик задания | `profiles.notification_prefs.job_draft` | адрес/описание/оплата/навыки; TTL 30 дней; без lat/lng/файлов; удаляется после публикации/вручную/с аккаунтом (J094) |
| Сохранённые поиски | `profiles.notification_prefs.saved_searches` | фильтры и флаг уведомлений; удаляются пользователем/с аккаунтом (J087/J092) |
| Push-подписки, настройки | БД | идентификаторы устройства (endpoint/ключи); лимит 10 на пользователя, мёртвые >90 дн удаляются (R055/R057); удаляются с аккаунтом |
| Логи | stdout Amvera | без паролей/координат; email маскируется (R058: `ab***@domain`) |
| Копии уведомлений (outbox) | БД | отправленные 30 дн / ошибочные 7 дн, автопочистка (R057); включают превью сообщений чата до 200 символов |
| Журнал действий администрации | БД (audit_log) | IP-адрес и ФИО(email) в JSON; удаляется старше 180 дн (R057) |
| Журнал ошибок (error_events) | БД | user_id + путь без query; **автопочистка >90 дн** ежедневной retention (R069); кнопка в админке — дополнительно (R039/R040) |
| UTM/активность | `profiles.acquisition`, `user_activity` | идентифицируемые (user_id), до удаления аккаунта (R060: политика 14.5 исправлена) |

## 2. Потоки и внешние сервисы

| Поток | Куда | Оценка |
|---|---|---|
| Основные данные | PostgreSQL (Amvera, РФ) | ок |
| Email (подтверждение/сброс) | SMTP из env (`SMTP_*`) | нужен договор/локализация провайдера; письма асинхронные через Celery, sync fallback |
| SmartCaptcha | `https://smartcaptcha.cloud.yandex.ru/validate`, form-urlencoded | Яндекс РФ; IP не передаём; fail-closed |
| MAX-верификация | MAX Bot API (РФ) | ок; согласие на передачу — в правилах/политике |
| Яндекс.Карты/Geocoder | JS API, `geocode-maps` | адрес задания уходит геокодеру; в privacy policy указать карты/геокодер |
| Яндекс Geosuggest | серверный `suggest-maps` (J079) | текст адреса уходит в Яндекс из POST-тела; ключ только в env, не в HTML; ответ не кэшируется |
| Аватары/фото заданий | диск Amvera | публично по назначению |
| Документы верификации | диск Amvera | owner/admin, no-store, attachment |
| Экспорт ПДн | JSON пользователю | без `password`; только свои данные |
| Удаление аккаунта | `delete_user_cascade` + файлы uploads | файлы удаляются с refcount (P1-14/J011) |
| **Web Push доставка** | **отключена по умолчанию** (`WEB_PUSH_ENABLED=0`, R088) | трансграничной передачи нет: VAPID-ключ не выдаётся, `POST /push/subscription` → 403 `push_disabled`, подписки не создаются, pywebpush не вызывается. Канал может быть включён только после декларирования по ст. 12 либо перехода на РФ-провайдера; уведомления — email и in-app; MAX используется только для верификации. Политика v1.5, п. 9.1/9.2 (R090) |

## 3. Реализованные меры

- Согласие 152-ФЗ при регистрации, `consented_at`; капча fail-closed.
- `email_verified default=false`, подтверждение email; повторная отправка с prefill.
- Per-IP лимиты register/login/reset/resend, Redis-cooldown (не in-process).
- Пароли: bcrypt `$2a$` (pgcrypto-совместимо), смена инвалидирует сессию.
- Публичный профиль без `contact/email/phone/religion`; контакты — после отклика.
- Документы верификации: owner/admin, `Cache-Control: private, no-store`, attachment.
- Удаление аккаунта удаляет аватар, документ, фото заданий (refcount общих файлов).
- Экспорт данных только владельцу.
- Гео: POST+сессия, округление, TTL 1 час, отсутствие координат в URL, без geolocationControl.
- SmartCaptcha: form-urlencoded, официальный endpoint, fail-closed.
- Логи: не печатать токены/пароли; секреты только env.
- Черновик и сохранённые поиски: только свой профиль, POST+CSRF, rate-limit; серверный черновик не хранит координаты/файлы.
- Geosuggest: адрес не в URL/access-логах, ключ не отдаётся в браузер.

## 4. Остаточные риски/задачи владельца

1. **SMTP-провайдер:** зафиксировать договор/локализацию и retention писем.
2. **Яндекс.Карты/Geocoder/Geosuggest:** отразить в политике обработку адреса задания
   и адресных подсказок; при необходимости — договор поручения. Политика должна
   упоминать серверный прокси Geosuggest.
3. **MAX Bot API:** проверить основание передачи идентификатора мессенджера.
4. **Логи Amvera:** настроить retention и исключить email/телефоны в error-логах.
5. **RKN:** уведомление об обработке ПДн — см. `docs/rkn_notification_fill.md`,
   обновить после добавления карт/геолокации.
6. **Cookie/consent:** аналитики нет; при добавлении — consent-баннер и категории cookie.
