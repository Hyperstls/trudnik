# Геолокация, карты и 152-ФЗ

**Дата:** 2026-11-02
**Область:** создание офлайн-задания, карта ленты, карточка задания, гео-фильтр.

## Модель данных

- `Job.address` — признак офлайн-задания. Если адреса нет, задание считается дистанционным: метка на карте не показывается.
- `Job.lat` / `Job.lng` — координаты **места работы**, не пользователя. Они публичны в карточке задания и используются для метки/маршрута.
- Отдельного хранения геопозиции пользователя (профиль, история, аналитика) нет.

## Форма задания (`/jobs/new`, `/jobs/<id>/edit`)

Доступно при заданном `YANDEX_MAPS_API_KEY` (карта). Геокодирование выполняется сервером через `YANDEX_GEOCODER_KEY` (J111), поэтому не зависит от прав JavaScript-ключа; если ключа нет или Яндекс недоступен — fallback на `ymaps.geocode`, затем ручной ввод адреса.

1. **Клик по карте / перетаскивание метки** — ставит координаты в `lat`/`lng` и подставляет `address`/`city`: сначала POST `/api/geo/geocode` (`mode=reverse`), при сбое — `ymaps.geocode`. Адрес обновляется принудительно, город — только если пуст.
2. **«Моё местоположение»** — `navigator.geolocation.getCurrentPosition` по явному клику пользователя. Координаты сразу попадают в скрытые `lat`/`lng` и **сохраняются только при отправке формы задания** как место работы. Отдельно местоположение устройства не пишется.
3. **«Найти по адресу»** — сначала POST `/api/geo/geocode` (`mode=forward`), fallback `ymaps.geocode`; адрес — данные задания, не пользователя.
4. **Подсказки адреса (J067/J079)** — при вводе от 3 символов браузер делает POST `/api/geo/suggest`; сервер вызывает Yandex Geosuggest с ключом из env. Адрес не попадает в URL/access-логи, ключ не отдаётся в HTML. При сбое/пустом ответе — fallback на `ymaps.geocode` (до 6 результатов). Список строится через `textContent`.
5. **Подтверждение точки (J067)** — после выбора/метки показывается блок «Проверить и подтвердить»; ручная правка адреса, новая метка или очистка сбрасывают подтверждение. Это UI-защита от случайной точки, серверная валидация не меняется.
6. **«Адрес по метке»** — обратный геокодинг через `/api/geo/geocode`, при сбое — `ymaps.geocode`; принудительно обновляет `address`/`city`.
7. **«Очистить метку»** — очищает `lat`/`lng`, метка скрывается.

Встроенный `searchControl` Яндекс.Карт не используется: его ошибки («Сервер не смог обработать запрос») не объясняют причину, а поиск дублирует поле адреса и кнопку «Найти по адресу».

Для дистанционных заданий карту заполнять не нужно — форма прямо это сообщает. Карта загружается API Яндекс.Карт (третья сторона, РФ); браузерный геолокатор в Яндекс не отправляется: `geolocationControl` удалён, координаты получает только наш JS.

## Карта ленты (`/jobs`)

- Показываются **только задания** с `address` + `lat/lng` (J028), без меток трудников.
- «Рядом со мной»:
  - координаты передаются **POST** на `/jobs/geo` с CSRF;
  - округляются до 3 знаков (~110 м) и кладутся в серверную сессию на 1 час;
  - в URL остаются только `geo=1&radius=...` — координат нет в истории браузера, referer и access-логах;
  - `nearby_jobs(p_lat,p_lng,p_radius)` используется только для выборки и ничего не сохраняет;
  - «Сбросить гео» отправляет POST `clear=1` и удаляет ключи из сессии;
  - старые ссылки с `lat/lng` поддерживаются для совместимости, но новый UI их не создаёт.
  - при активном гео на карте рисуется круг радиуса (`ymaps.Circle([[lat,lng], radius_m]]`); центр в HTML округлён до 3 знаков (J066).
- `geolocationControl` Яндекс.Карт удалён, чтобы не передавать геолокацию третьей стороне.

## Карточка задания (`/jobs/<id>`)

- Показывает адрес/город, если они заданы.
- При `address + lat/lng`: встроенная карта (если есть ключ), «Открыть на карте» и «Маршрут» (внешние ссылки на Яндекс.Карты).
- Без координат, но с адресом — «Найти адрес»; только с городом — «Найти город».
- Внешние ссылки открываются в новой вкладке с `rel="noopener noreferrer"`, передают только координаты задания.

## 152-ФЗ: принятые меры

- **Минимизация:** геопозиция пользователя округляется до 3 знаков; точные координаты не сохраняются.
- **Минимизация срока:** серверная сессия гео-фильтра — 1 час.
- **Отсутствие URL-утечки:** координаты не попадают в GET-параметры, историю, referer и access-логи.
- **Явное действие:** браузерный геолокатор вызывается только по кнопке; без разрешения пользователя ничего не происходит.
- **Разделение данных:** координаты задания (публичные) и координаты устройства (временные, только для поиска) не смешиваются.
- **Третьи стороны:** карты и геокодер — Яндекс.Карты (РФ); серверный прокси передаёт Яндексу только адрес задания или координаты метки. Ключ Geocoder API не попадает в HTML/JS.
- **Серверный прокси:** `/api/geo/geocode` доступен только авторизованным, принимает POST ≤ 4 КБ, ограничен 60 запросами/мин на IP; результаты кешируются на 10 минут, чтобы не расходовать квоту и не повторять одинаковые запросы. Используется Geocoder API v1 с fallback на legacy `/1.x/`; в лог попадает только HTTP-статус, без адреса и ключа. Сервер обязан отправлять `Referer`, совпадающий с доменом в ограничении ключа (`YANDEX_GEOCODER_REFERER`, по умолчанию `WORKER_SITE_URL`), иначе Яндекс отвечает `403 Invalid api key`; новые ограничения ключа применяются до 15 минут.
