# Архитектурное ревью 2026-09: упрощение без потери качества

> Фокус владельца: где перемудрено, что можно сделать проще и надёжнее.
> Метод: чтение горячих файлов + опыт волн UX/безопасности (2026-09). Не путать с `architect_audit_prompt_v2.md` (тот — чек-лист вопросов; здесь — находки и решения).

## Топ перемудрённого (по убыванию выгоды упрощения)

### 1. `login_required` — 4–5 подзапросов на каждый запрос (decorators.py:16-173)
Сейчас на КАЖДЫЙ запрос страницы: JWT decode → jti-blacklist (Redis) → pwd_changed_at (Redis-cache + PostgREST) → user_exists (Redis-cache + PostgREST) → suspended (Redis-cache + PostgREST). Даже с кэшем — это лес ветвлений и скрытых запросов на горячем пути.
**Упрощение:** одна «сводка валидности сессии» на пользователя: ключ `session_check:{user_id}` (Redis, TTL 60с) с полями `{exists, suspended, pwd_changed_at}` — одна запись вместо трёх кэшей. Инвалидация пишется при смене пароля/удалении/заморозке. Результат: 1 Redis GET на запрос вместо 3–4 веток; код декоратора −60 строк.
**Риск:** низкий (поведение то же). **Эффорт:** S.

### 2. `postgrest_client.py` — 867 строк
Содержит: CircuitBreaker (теперь Redis-shared), retry с backoff, caller-audit (inspect stack-walk), admin_context, normalize_endpoint, mock-инъекцию, 2 сессии. Работает, но тяжело читается.
**Упрощение:** НЕ переписывать. Точечно: (а) `_get_caller_info` — после перевода всех admin-вызовов на `admin_context()` убрать inspect-fallback (он уже почти не нужен); (б) вынести CircuitBreaker в `app/utils/circuit_breaker.py` (файл по делу). **Эффорт:** S.

### 3. `app/utils/__init__.py` — 242 строки ре-экспорта + mock-инъекция
Танец «импорт mock → инъекция в _pgrest → ре-экспорт» — источник circular-import багов (2 зафиксировано за сессию). 
**Упрощение:** убрать инъекцию в модули: mock активируется ТОЛЬКО через подмену `requests.*` (она уже есть в mock_postgrest) — тогда `app/utils/__init__.py` становится чистым ре-экспортом, без `_pgrest._*` присвоений. **Риск:** средний (много тестов опираются на текущее поведение) — делать отдельной волной с полным гейтом. **Эффорт:** M.

### 4. Self-heal DDL каждые 120с (maintenance_tasks.ensure_postgrest_role_grants)
DDL в рантайме по таймеру — антипаттерн, прижившийся из-за сброса грантов Amvera CNPG.
**Упрощение:** после восстановления на msk1 проверить, сбрасываются ли гранты там; если нет — перевести self-heal из «каждые 120с» на «при старте + раз в сутки». **Эффорт:** S (env-флаг).

### 5. `jobs.py` — 1259 строк, `index()` собирает страницу из ~6 источников inline
geo-RPC + навыки + отклики + blacklist + рейтинги + избранное + пагинация — всё в одной функции.
**Упрощение:** выделить `app/services/catalog_service.py::build_index_query(...)` (чистая сборка query) и `enrich_cards(jobs, user_id)` (метки). Без смены контрактов. **Эффект:** jobs.py читается, фильтры тестируемы юнитами. **Эффект:** M.

### 6. Двойные механизмы, закрытые в этих волнах (уже упрощено)
- JWT-claims: 124 (pre-request) + 125 (JSON-политики) → консолидировано на 125 (146, pre-request стал no-op).
- Подтверждения: нативный confirm + кастомный showConfirm → только showConfirm.
- Пароли: 3 политики → одна (validate_password 8+).
- Избранное: 3 реализации → favorites_service.
- Чат-доступ: 4 копии → chat_access.
- Навыки: DELETE+N×POST → RPC sync_user_skills.

### 7. Шаблоны — inline-JS в шаблонах
Часть логики живёт в inline-скриптах шаблонов (index.html apply-flow, my_jobs bulk). Паттерн выноса доказан: chat.js, invite-worker.js, skills-multiselect.js.
**Упрощение:** продолжить вынос в static/js/*.js по мере касания страниц (не отдельной волной). **Эффект:** кэшируемость, CSP-чистота, тестируемость.

## Что НЕ упрощать (риск > выгода)
- PostgREST-единая точка доступа + RLS — ядро безопасности.
- Outbox-паттерн уведомлений — надёжность доставки.
- Redis-сессии — масштабирование воркеров.
- `apply_job_atomic` и прочие SECURITY DEFINER RPC — атомарность.

## Рекомендуемый порядок
S-эффекты сразу (1, 2, 4 — при восстановлении), M — отдельными волнами (3, 5) с полным гейтом.
